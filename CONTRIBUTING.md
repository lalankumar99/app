
# 🤝 Contributing Guidelines

Thank you for your interest in contributing to the Coaching App Template!

We welcome suggestions, bug reports, documentation improvements, and code contributions that help improve this project.

## 📌 How to Contribute

### 1. Fork the Repository

Fork the project to your GitHub account.

Repository: https://github.com/lalankumar99/app

### 2. Clone Your Fork

```bash
git clone https://github.com/YOUR_USERNAME/app.git
cd app
```

Replace `YOUR_USERNAME` with your GitHub username.

### 3. Create a Branch

```bash
git checkout -b feature/your-feature-name
```

Use a descriptive branch name, such as:

- `feature/student-dashboard`
- `fix/login-screen`
- `docs/update-readme`

### 4. Install Dependencies

Make sure Flutter is installed, then run:

```bash
flutter pub get
```

### 5. Make Your Changes

Follow these guidelines:

- Write readable and maintainable Dart code.
- Follow standard Flutter conventions.
- Keep the project structure organized.
- Avoid adding unnecessary dependencies.
- Update documentation when necessary.
- Never commit passwords, API keys, or private credentials.

### 6. Test Your Changes

Run the following commands before submitting your changes:

```bash
flutter analyze
flutter test
```

Fix any relevant errors before opening a pull request.

### 7. Commit Your Changes

```bash
git add .
git commit -m "Describe your changes"
git push origin feature/your-feature-name
```

### 8. Open a Pull Request

Open your fork on GitHub and create a pull request targeting the `main` branch of the original repository.

Include:

- A clear title
- A description of your changes
- Steps to reproduce any bug fixes
- Screenshots for UI changes, when applicable

## 🐛 Reporting Bugs

When reporting a bug, include:

- A clear description of the problem
- Steps to reproduce it
- Expected behavior
- Actual behavior
- Relevant error messages or screenshots

Do not include passwords, access tokens, or other sensitive information.

## 💡 Suggesting Features

Feature suggestions should explain:

- The problem the feature solves
- How the feature could work
- Why it would benefit the project

## 📐 Code Style

- Follow Dart and Flutter coding conventions.
- Use meaningful variable and function names.
- Prefer small, reusable widgets.
- Keep formatting consistent.
- Add comments when they improve clarity.

Format Dart files using:

```bash
dart format .
```

## 📄 Documentation

Keep the README and other documentation accurate and up to date.

Clearly distinguish implemented features from planned features.

## 📜 Code of Conduct

Be respectful, constructive, and welcoming to everyone.

Harassment, abusive behavior, and discriminatory comments are not acceptable.
